# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

AI Buddy: a Tamagotchi-style talking character for the Waveshare
**ESP32-S3-Touch-AMOLED-1.75C** (466x466 round QSPI AMOLED, CST9217 touch,
ES8311 speaker codec + ES7210 mic codec, AXP2101 PMIC, 16MB flash, 8MB octal
PSRAM).

Flow: tap the screen, then speak. The device records until you go quiet,
sends the audio to Deepgram (speech-to-text), sends the transcript to Claude
(`/v1/messages`, rolling history), then shows the reply and streams it
through ElevenLabs TTS to the speaker. All API calls go directly from the
device over HTTPS.

**The user builds and flashes.** Don't run `pio run` / upload / monitor;
hand over the command and ask for the build output or serial log.

## Build / flash

```bash
cp src/secrets.example.h src/secrets.h   # WiFi creds (gitignored)
# ANTHROPIC_API_KEY, DEEPGRAM_API_KEY, ELEVENLABS_API_KEY must be in the
# shell env or a project-root .env -- scripts/gen_api_keys.py writes them
# into the gitignored src/api_keys.h at build time.
pio run -e ai-buddy                      # build
pio run -e ai-buddy -t upload            # flash
pio device monitor -b 115200             # serial log
```

The first build downloads managed components (pinned in `dependencies.lock`,
declared in `src/idf_component.yml`) into `managed_components/`.
**Don't add dependencies to `src/idf_component.yml`.** It forces a re-solve
that crashes PlatformIO's pinned component manager on lvgl 9.6 metadata.
Vendor new components into `components/` instead (see
`components/README.md`; the touch driver lives there).
Finder `.DS_Store` files inside `managed_components/` trip the component
manager's hash check ("were modified on the disk");
`scripts/strip_ds_store.py` deletes them before every build.

Toolchain notes (see `platformio.ini`):
- `platform = espressif32@6.9.0` (ESP-IDF 5.3) is pinned on purpose:
  ESP-IDF 6.x breaks `esp_codec_dev@1.4.0`.
- `platform_packages = tool-cmake @ ~3.30.2`: the platform's default CMake
  3.16 is x86-only and this Mac has no Rosetta.

## Where the board code came from

Copied from `../../bark-notify/amoled`, which is verified on this exact
unit (display, WiFi, mic and speaker). That project's README and git log
record the bring-up history. Board-layer files, which you shouldn't change
without a reason:

| File | Role |
|---|---|
| `board_config.h` | Pin map. **MCLK is GPIO16 on the 1.75C** (GPIO42 on the plain 1.75). Getting it wrong makes audio silent in both directions. |
| `board_bringup.cpp/.h` | I2C, AXP2101 rails, QSPI, SH8601 panel, LVGL |
| `axp2101.*`, `i2c_device.*` | PMIC driver. ALDO1 powers the codecs; don't blanket-disable the LDOs |
| `audio_codec.*`, `box_audio_codec.*` | ES8311 + ES7210 through `esp_codec_dev`. Runs at 24kHz, the vendor-tuned rate: TDM `bclk_div` is hardcoded for it |

App-layer files (free to rewrite):

| File | Role |
|---|---|
| `main.cpp` | Bring-up, then `conversation_task`: idle → listening → thinking → speaking, plus dim (1 min) / sleep (3 min, or BOOT button) and wake. Taps, BOOT presses and volume swipes set atomic flags and wake the task |
| `settings.*` | NVS-backed settings (speaker volume). NVS init lives here, called first in `app_main` |
| `wifi_sta.*` | Joins the strongest network from `WIFI_NETWORKS` (secrets.h); a background task rescans/reconnects when the link drops |
| `app_config.h` | All tunables: Claude model/history, system prompt, voice, VAD thresholds |
| `buddy_ui.*` | Mershy: a cartoon portrait of Mehrshad (base image) with brows/eyes/mouth layers swapped by a 33ms `lv_timer` for blinks, glances, moods and lip-sync. Missing art parts fall back gracefully |
| `mershy_assets.h`, `assets/mershy.bin` | Generated by `art/build_assets.py` from `art/source/*.png` (see `art/README.md`). Embedded via `EMBED_FILES` + `board_build.embed_files` |
| `recorder.*` | Mic capture into a 15s PSRAM buffer with a dBFS silence gate |
| `stt_deepgram.*`, `claude_client.*`, `tts_elevenlabs.*` | One API each. Claude streams (SSE, `claude-sonnet-5`, thinking disabled) |
| `reply_stream.*` | Runs the Claude stream in a background task, parses the leading mood/volume tags, and hands `main` speakable pieces: the first sentence as soon as it's complete, then everything complete so far. Each piece is one ElevenLabs request (with `previous_text` for continuous intonation) |
| `audio_player.*` | Speaker output from a 30s PSRAM ring buffer, played by its own task (core 1, prio 8). TTS downloads into it faster than real time, so the next reply piece downloads while the current one plays (no gaps between pieces). Drives the mouth level from what's actually playing |
| `http_util.*` | `HttpConn`: one persistent keep-alive HTTPS connection per API, built on `esp_http_client_perform()` with the body streamed via `HTTP_EVENT_ON_DATA`. Don't switch back to manual `open`/`read`: in IDF 5.3 only `perform()` resets the client state for connection reuse |

Controls: tap = talk (fires on release), vertical swipe = volume, BOOT =
sleep/wake, PWR held 4s = power off (PMIC, hardware). Asking Mershy to be
louder/quieter makes Claude add a `[volume up|down|N]` tag, stripped and
applied by `claude_client` / `main`.

Claude replies start with a mood tag (`[happy]` etc., required by the
system prompt). `reply_stream` strips it and the UI changes the face to
match. History keeps the raw tagged text.

While the user is talking, `warm_task` (main.cpp) pre-opens all three
connections so the requests after it skip their TLS handshakes.

Each exchange logs `latency:` lines (STT time, Claude time-to-first-text,
end of speech → first audio) for tuning.

After adding or changing art in `art/source/`, regenerate the assets
(committed, so builds don't need Python):

```bash
art/.venv/bin/python art/build_assets.py
```

One-time setup: `python3 -m venv art/.venv && art/.venv/bin/pip install pillow numpy`.

Audio input is interleaved 2-channel: ch0 = mic, ch1 = AEC reference.
Playback is opened as 2-channel too, so mono PCM must be written as L=R
pairs (see `tts_elevenlabs.cpp`).

**Latency (2026-09-24, verified):** end of speech → first voice is ~2.2s
(Deepgram ~0.3-1s, Sonnet first text ~1.1s, ElevenLabs first audio ~0.3s),
down from ~9s. What got it there: 64KB TCP send buffer (uploads), connection
warm-up during listening, streamed Claude reply spoken per sentence, and the
buffered audio player. Keep the TCP *receive* window small (see
`sdkconfig.defaults`): 64KB caused multi-second stalls mid-word.

**Verified on hardware (2026-09-24):** the full tap → listen → Deepgram →
Claude → ElevenLabs loop works. Touch works with the plain 1.75's vendor
settings (`TOUCH_PIN_RST` GPIO40). `claude-opus-5` rejected the
`output_config.effort` parameter with a 400 (with the server-side fallback
beta on), so no request sends `effort`.

Known harmless boot errors: TCA9554 IO expander NACK (non-fatal), and
`sh8601: swap_xy is not supported`.

## Reference firmware

The known-good Waveshare factory image is
`../../bark-notify/amoled/ESP32-S3-Touch-AMOLED-1.75C-FactoryOnly-260114.bin`.
Flash it to confirm the hardware works if audio or the display ever look dead.

## Conventions

- Flat `src/`, C++ with ESP-IDF APIs, LVGL 9 via `esp_lvgl_port`.
  Wrap LVGL calls in `lvgl_port_lock()`/`lvgl_port_unlock()`.
- Secrets go only in the gitignored `src/secrets.h`, `src/api_keys.h`, `.env`.
- `sdkconfig.ai-buddy` is generated from `sdkconfig.defaults`. After
  changing the defaults, delete it so it regenerates.
